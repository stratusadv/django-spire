## End State

An external app declares its metric structure in a `Metric` subclass (`Metric.Domain`, `Metric.SubDomain`, `Metric.StatisticGroup`, `Metric.Statistic`, `Metric.Target`), and `manage.py metric_build` idempotently creates/syncs those Domain/SubDomain/StatisticGroup/Statistic rows; `metric.check()` reports missing structure (DB locally, API probe remotely) and `metric.record()` writes values local or to a configured remote target — covered by tests and a docs page.

## Observable Concern

The namespaced key contract (`sales__web`, `sales__orders__created`) becomes the public API for record/check, and the `Domain.key` migration must backfill keys for existing rows. Get these two right first or build/check/record (and anything already referencing keys, e.g. the tracking middleware settings) drift silently.
